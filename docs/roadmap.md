# 앞으로 할 일 · 생각해 둔 것

정해진 계획이 아니라, 논의하면서 나온 방향과 아직 확인하지 않은 후보를 적어 둔 곳입니다.
`[추정]`은 직접 확인하지 않은 내용입니다.

## 목표

가지고 있는 강의 녹음·영상이 많습니다. 이것을 받아써서 노트로 만들고 공부하는 데 쓰는 것이 lnb의 다음 방향입니다.

1. **폴더째 받아쓰기** — 끊겨도 이어서 하기 (구현됨, 아직 출시 전)
2. **강의 → 노트 → 검사**를 한 흐름으로 잇기 (아직 설계 전)

## 1. 폴더째 받아쓰기에서 정한 것

- **자막은 원본 옆이 아니라 별도 폴더에, 같은 하위 구조로.** `lnb transcribe ~/강의 -o ~/강의자막`.
  원본 폴더를 건드리지 않고, 나중에 노트·검사 결과도 작업 폴더에 모인다. `-o`가 없으면 예전처럼 원본 옆.
- **"끝났다"의 기준은 자막 파일이 있는지.** 자막은 다 만든 뒤에야 제 이름이 되므로 반쪽 파일이 남지 않는다.
  따로 기록 파일을 두지 않는다 — 기록과 실제 파일이 어긋날 일이 없다.
- **자막 이름에 모델 이름을 넣는다.** `1강 (whisper large-v3-turbo-q5_0).srt`.
  모델을 바꾸면 새 자막이 따로 생기고 예전 것은 남는다. 두 판을 나란히 비교할 수 있다.
- 같은 폴더에 `1강.mp4`와 `1강.m4a`가 함께 있으면 `1강.mp4 (whisper …).srt`처럼 확장자까지 넣는다.

**남은 문제**
- 한 강의에 자막이 여러 판 있으면 `lnb text`·`lnb check`가 어느 것을 쓸지 정해야 한다 — 2번 설계 때.
- 이번 변경 전에 만든 `<이름> (whisper).srt`는 "끝난 것"으로 보지 않아, `lnb transcribe`를 다시 돌리면 다시 받아쓴다.

## 왜 whisper.cpp인가

원본 Whisper(OpenAI)는 Python으로 실행한다. lnb는 처음부터 ggml-org의 whisper.cpp(C/C++)를 썼는데,
그 이유를 적어 둔 기록은 없다. 이 맥에 이미 쓰던 앱의 whisper.cpp용 모델이 있었기 때문으로 보인다 `[추정]`.

맥에서 whisper.cpp가 유리한 일반적인 이유:
- 설치가 가볍다 — 원본은 PyTorch(수 GB)와 Python 환경이 필요하고, whisper.cpp는 `brew install whisper-cpp`로 끝난다
- 애플 칩 GPU(Metal)를 바로 쓴다 — 원본은 맥에서 주로 CPU로 돈다 `[추정, 실측 안 함]`
- 크기를 줄인(양자화) 모델로 8GB 맥에서도 large 모델을 돌린다
- 모델 자체는 같은 Whisper라 받아쓰기 품질은 거의 같다 (양자화로 인한 차이만)

## ggml-org 쪽에서 써 볼 만한 것 (모두 `[추정]`, 확인 전)

ggml-org는 Georgi Gerganov가 시작한 오픈소스 조직이다(GitHub, 2023-05 생성, 코드 MIT).
llama.cpp · whisper.cpp · ggml(둘이 함께 쓰는 계산 라이브러리)을 만든다. 모델 파일은 Hugging Face에 있다.

| 후보 | 쓸 자리 | 메모 |
|---|---|---|
| **Silero VAD** (whisper.cpp) | 말소리가 있는 구간만 받아쓰기 | **채택** — 아래 시험 결과 |
| **large-v3 정식판** (whisper.cpp) | 받아쓰기 정확도 | turbo보다 느리고 조금 정확. 모델 이름이 자막 이름에 들어가므로 나란히 비교하기 쉽다 |
| 작은 언어 모델 (llama.cpp) | 강의 수백 개의 한 줄 분류·목차 초안 | 노트 작성은 Claude보다 크게 떨어진다. 8GB 맥에선 작은 모델만 |
| 그림 읽는 모델 (llama.cpp 멀티모달) | 판서·슬라이드 글자 읽기 | 수식 인식은 큰 모델보다 많이 약할 것 |

## 유료 AI 없이 로컬에서 — 토의 중 (2026-11-19)

아직 결정한 것은 없다. 나중에 이어서 논의하려고 적어 둔다.

### 구조: AI가 필요한 단계는 하나

| 단계 | AI |
|---|---|
| fetch · transcribe(whisper, 이미 로컬) · text · frames · pages | 필요 없음 |
| **노트 쓰기** | 필요 — 지금은 Claude Code 하네스 + 스킬 + Claude |
| check | 필요 없음 |

그래서 로컬로 바꿀 것은 "노트 쓰기" 한 단계와 그것을 돌리는 틀뿐이다.

### 두 가지 길

1. **공개 에이전트 하네스 + 로컬 모델 서버**(llama.cpp · Ollama 등) — 자유도는 높지만 로컬 모델의 여러 단계 도구 호출이 아직 불안정하다 `[추정]`
2. **lnb 안에 작은 하네스** — 순서가 정해진 일이라 범용 에이전트가 필요 없다:
   `받아쓰기 → 본문 → 로컬 모델이 노트 작성 → lnb check → 틀리면 검사 결과를 돌려주고 다시 → 통과까지`.
   출발점: `tools/run_gateway.py`(지시서를 보내고 노트를 받는다).

   **주의 — `lnb check` 통과는 "근거 있는 노트"라는 뜻이 아니다.** 검사기는 *알아본 형식의* 인용과 검산식만 확인한다.
   인용을 아예 안 달거나 다른 따옴표·형식을 쓰면 검사할 것이 없어 통과한다. 인용 밖의 설명문도 보지 않는다.
   그래서 이 고리를 채점자로 쓰려면 먼저 필요한 것:
   - **형식·분량 관문** — 절마다 인용이 최소 몇 개 있는지, 알아보지 못한 인용 꼴(굽은 따옴표 등)이 있으면 실패로
   - **사람(또는 다른 모델) 검토 단계** — 검사기 통과 뒤 설명문을 읽어 보는 단계

근거와 한계: `experiments/`에서 공개 모델 다섯 개의 노트를 검사기로 채점했다(문제 A3 B2 C1 D3 E0).
그러나 문제 수가 적다고 좋은 노트가 아니다 — 사람이 읽은 평가로 C는 가장 부족했는데 문제가 1개뿐이었다. 둥근따옴표(“ ”)로 인용해 검사기가 인용을 하나도 보지 못했기 때문이다(`experiments/2026-09-23_blind-read.md`).
위 관문이 필요한 이유가 바로 이것이다. 또 외부 서버의 큰 모델이었고, 로컬 크기 모델로는 아직 안 해 봤다.
어려운 곳: 판서 그림 읽기 — 로컬 멀티모달 모델은 수식에 약할 것 `[추정]`.

### 학습도우미 (가칭) — 질의응답

- **RAG를 바탕으로**: 질문 → 대본·노트에서 관련 부분 검색 → 모델에 함께 전달 → "몇 강 몇 분" 출처가 붙은 답. lnb의 "원문과 대조" 방향과 같고, 강의를 더해도 다시 학습할 필요가 없다
- **파인튜닝은 형식용**: 말투·노트 형식에는 맞지만 사실을 외우게 하면 지어낼 위험이 크다. 맥에서는 MLX LoRA `[추정]`
- 장기: 노트를 쓰며 고친 자막이 쌓이면 받아쓰기 추가 학습 데이터가 된다 (GPU 서버 필요)

### 모델 시험 방법 (OpenRouter)

- OpenRouter는 **1차 거르기**로만 쓴다. 같은 모델이라도 로컬에서는 양자화(4비트 등)·실행 프로그램·대화 틀(chat template)·샘플링 기본값이
  달라 품질이 꽤 달라질 수 있다. "이 크기면 충분하다"는 결론은 **실제로 로컬에서 같은 시험을 돌려 본 뒤에** 내린다. 속도·메모리도 실제 기계에서
- 크기별로 2~3개(약 30B · 약 70B · 100B 이상)에 같은 일(대본으로 노트 쓰기, 대본을 준 질의응답)을 시키고 Claude와 나란히 비교 → "어느 크기면 충분한가"가 필요한 메모리를 정한다
- 시험 자료는 공개 강의(Strang)만 — 개인 소장 강의는 외부 서버로 보내지 않는다
- 받아쓰기(whisper) 모델은 OpenRouter에 거의 없다 → 맥에서 비교

| 후보 | OpenRouter |
|---|---|
| 작은 언어 모델 — 강의 분류·목차 초안 | 됨 |
| 그림 읽는 모델 — 판서·슬라이드 | 대체로 됨 `[추정]` |
| whisper large-v3 정식판 | 안 됨 (맥에서) |
| 학습도우미 질의응답 (RAG) | 됨 |

### MinerU 속도

모델이 든 도구 중 느린 것은 MinerU(교재 PDF → md)뿐이다. 직접 옮기기(ggml-org가 whisper에 한 것처럼)는 마지막 수단 —
여러 모델을 이은 구조라 whisper보다 몇 배 어렵다. 먼저 확인할 것: MinerU에 애플 칩용 실행 방식(MLX)이 이미 있는지 `[추정]`,
수식이 적은 교재는 `lnb pages`의 글자층 추출로 충분한지.
